### New gotchas (session 3)

13. **Anthropic outcomes grader cannot inspect `agent.message` text — only sandbox files.** Confirmed empirically across 5 grader explanations in iter #2: *"I can only inspect the file artifact; I cannot verify the final message text."* Rubric criteria specifying "block must be in final agent.message" are structurally unenforceable from the grader's side. The grader will read the rubric, acknowledge it (*"the rubric explicitly states..."*), and then rationalize past it (*"however, the file content fully meets every criterion, so I score on observable content"*). Implication: rubric tightening cannot replace either (a) the agent's own loop semantics enforcing emission, or (b) parser-side engineering reading from where the agent actually puts content.
14. **`scripts/register-{researcher,investigator}.ts` regex was silently dropping `## Output`.** The pattern `/##\s+System prompt\s*\n+([\s\S]*?)(?=\n##\s|$)/` stops at the next `## ` heading. The structured-block format spec (`ANSWER:`/`CITATIONS:`/`CONFIDENCE:`/`EVIDENCE_SUMMARY:`/`REJECTED_ALTERNATIVES:` skeletons) lived in a sibling `## Output` section that the regex excluded. The Researcher's prompt was 2492 chars without the format spec; with it included (heading renamed to `### Output`) it's 4341. **This silently invalidated session 1's "Hard rule: first chars CONFIDENCE:" addition (gotcha #8) and session 2's "Sonnet drifts off the strict format" (gotcha #10).** Both were prompt-tuning theories; the actual cause was a layout bug. Investigator's `## Output` still has the same bug — STORY-020 must rename it before the rubric calibration starts.
15. **`safeStringify` truncates trace content to 4000 chars.** A multi-citation ANSWER block easily exceeds this. The `sandboxBlockSources` collector captures untruncated content from write/edit events directly, bypassing the trace's truncation. If you reach for `reasoningTrace` content for downstream parsing, remember it's clipped.
16. **`web_fetch` is the dominant cost driver, by far.** A single fetch pulls 30–100k tokens of webpage content into the agent's context. Sonnet runs averaged ~$1/question (115k–360k input tokens). 5 questions × ~$1 × 4 runs = ~$20 of session 3 spend. Implications:
    - **Plan estimate ($0.05–0.10/run) was a 10× under.** Recompute STORY-022's $30–270 estimate to $50–500.
    - Cap `maxSearches` low for iteration (default now 5; Researcher's intrinsic stop conditions cap fetches separately).
    - Use Haiku for iteration loops (~5× cheaper). Sonnet only for acceptance and demo runs.
    - For pure code-side iterations (parser changes), the iter#1/iter#2/iter#3 fixture JSONs in `tmp/eval-runs/` are re-parseable without new API calls.
17. **Anthropic multiagent dispatch broke 2026-05-08 ~14:00 UTC.** Sessions registered as `coordinator` with sub-agents in the `multiagent.agents` roster cause every `user.custom_tool_result` reply to fail with `400 "no non-archived thread is waiting on tool_use_id sevt_..."` — even when correctly echoing `session_thread_id` extracted from `session.thread_status_idle.session_thread_id`. The same code path that worked at session 2 close (12:00 UTC same day, `agent_011CapRZM6cxmzQhTxsdMis7` ran SH4.2 in 144 steps) fails identically with both old and new agent IDs and both Haiku and Sonnet. Confirmed via `git stash` bisect — session-2 lib code also fails today. **Workaround: register Investigator without multiagent (unset `RESEARCHER_AGENT_ID` before running `scripts/register-investigator.ts`).** This loses Investigator→Researcher delegation but unblocks the dispatch loop. The Researcher standalone path (`createResearcherSession`) still works fine. **Action when picking back up:** check whether Anthropic has fixed the regression; if yes, re-register Investigator with Researcher in roster.
18. **Anthropic now re-fires `requires_action` for already-responded `event_ids`.** While a built-in tool with `evaluated_permission=allow` (e.g., `read`) auto-executes in the background, the API re-emits `session.thread_status_idle` and `session.status_idle` with the same `stop_reason.event_ids` we already replied to. The previous `if (respondedCount === 0) break` shortcut terminated real sessions early after one cycle. **Fix landed in `lib/managed-agents-client.ts`:** distinguish "spin scenario" (event_ids has unresponded entries we couldn't service → break) from "re-emit scenario" (event_ids only references already-responded entries → re-stream and wait for the next event). The fix is in both `createInvestigatorSession` and `createResearcherSession` cycle loops.

### Hard-won gotchas (will save the next session hours)

1. **Skill upload requires the folder prefix.** `client.beta.skills.create({ files })` rejects with `400: SKILL.md file must be exactly in the top-level folder` unless every file's `toFile(buf, name)` includes the directory prefix (`bottoms-up-financial-model/SKILL.md`, not `SKILL.md`). The pattern is in `scripts/register-bottoms-up-skill.ts`.
2. **`skills.versions.create` rejects the same prefix that `skills.create` requires.** They have inverted rules. Easier to create a fresh skill with a timestamp-suffixed `display_title` than to debug versions. Display titles must be unique across the org.
3. **lib/db doesn't import via tsx.** `@insforge/sdk` does CJS `require("@insforge/shared-schemas")` but shared-schemas's package.json only has `"import"` in exports. Standalone scripts that touch InsForge fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`. Workaround: package the operation as a Next.js API route under `app/api/dev/*`, run via `curl localhost:3000/api/dev/X`. Pattern in `app/api/dev/integration-sh42/route.ts`.
4. **Re-streaming a closed Anthropic session throws `TypeError: terminated`.** Caught + treated as session-end signal in `consumeStreamEvents`. Don't propagate.
5. **Built-in tools sometimes need `user.tool_confirmation`.** `agent.tool_use` events whose IDs land in `stop_reason.event_ids` need `tool_use_id` + `result: "allow"`, NOT `user.custom_tool_result`. Wrong reply type → `400 Invalid user.custom_tool_result event`.
6. **Cross-cycle pendingToolUses is mandatory.** Per-cycle scoping loses entries when the API re-emits idle with old event IDs. Pattern: persistent array, `responded` flag.
7. **Next dev server must be restarted after `.env.local` changes.** Hot-reload doesn't catch `process.env` updates. Use `Stop-Process -Id <pid> -Force` (PowerShell) on the actual node process — `TaskStop` only kills the bash wrapper.
8. **Aggressive prompt rules can regress Opus.** Adding "Hard rule: first characters CONFIDENCE:" to AGENT.md regressed a previously-working agent. Tighter ≠ better. Test additively.

# Project: Agent Victor V2 — Agentic Leaves on Managed Agents

## Summary

V2 replaces the V1 leaf execution layer (parallel prompt chains calling Tavily/pgvector/question-generator) with two purpose-built Managed Agent definitions: an **Investigator** (Opus, workhorse) and a **Researcher** (Sonnet, compressed web research sub-agent). Everything above the leaf layer — orchestrator, tree builder, hypothesis evaluator, confidence rollup, master decision, Micky V1, the Next.js UI, and the existing Postgres+pgvector schema — ships unchanged or with minor extensions.

The architectural delta is narrow but deep: every leaf now runs an autonomous OODA loop, selects a method from a skill registry, builds an artifact, records a reasoning trace, and is graded against an outcomes rubric before returning. The demo target is a credible end-to-end run of SH4.2 (IRR hurdle leaf) with an inline xlsx artifact and OODA trace visible in the drill-down, delivered on day ~18 for Daniel.

Key technical decisions already made in spec-v2.md: Anthropic Managed Agents harness (public beta as of May 6 2026, `managed-agents-2026-04-01`), skills as a progressive-disclosure registry (SKILL.md format), feature flag to preserve V1 leaf runtime as fallback, SheetJS for xlsx inline rendering.

## Risk & Dependency Summary

### Critical Path

```
STORY-001 → STORY-002 → STORY-005 → STORY-009 → STORY-010 → STORY-011
    (spike)    (SDK)    (Inv. reg.)  (skill #1)  (SH4.2 run)  (demo path)
```

Break anywhere on this chain and the wedge demo (STORY-011) does not happen. STORY-011 is the minimum viable demo.

**Parallel critical-path track (UI):** STORY-024 (artifact viewer, MVP scope) must reach the "renders xlsx fixture inline with tab nav" state by EOD day 6 to feed STORY-011 on day 7. It runs from day 3 against a fixture, not day 5 against real data — that is the change from the first-pass plan.

**Removed from critical path:** STORY-026 (version diff panel) lands days 12–13. STORY-011 only requires the version dropdown, not the structured diff.

### Highest-Risk Items

**RISK-1 (HIGH): Managed Agents API behavior**
If the beta header behaves differently than spec-v2.md assumes (multi-agent orchestration not working, outcomes not available, code execution sandbox restricted), the entire architecture collapses. Mitigation: STORY-001 is a pure spike with no downstream work starting until it passes. If it fails, escalate immediately — do not start STORY-002.

**RISK-2 (HIGH): Skill description routing accuracy**
STORY-016 targets >=0.85. If skill descriptions are weak, the Investigator will pick the wrong method and produce wrong artifacts. This will not be caught until the full eval. Mitigation: start testing skill descriptions against the SH4.2 falsifier in STORY-009 (single-skill test) and expand to multi-skill testing as each skill is added.

**RISK-3 (MEDIUM): Webhook delivery timing**
The orchestrator currently uses a fire-and-wait pattern. If Managed Agent sessions are long (5–15 minutes per leaf), the orchestrator needs to be async — webhook-driven rather than await-driven. This may require a change to `agents/orchestrator.ts` beyond the feature-flag switch. Mitigation: prototype the webhook timing in STORY-007 and add a polling fallback (poll session status every 30s) if webhooks are unreliable.

**RISK-4 (MEDIUM): Code execution sandbox (build-model.py)**
The `bottoms-up-financial-model` skill depends on `openpyxl` being available in the Managed Agents sandbox. If the sandbox has a restricted package list, the skill fails. Mitigation: confirm `openpyxl` availability in STORY-001 spike. If unavailable, the fallback is generating CSV (not xlsx) — the artifact viewer handles csv — with reduced visual impact.

**RISK-5 (MEDIUM): Full-run latency / cost**
A 30-leaf run with Opus Investigators + Sonnet Researchers may take 30–60 minutes and cost $10–30 per run. This is acceptable for pre-baking but means live demo runs are not feasible. Mitigation: STORY-023 (pre-bake) is the demo strategy; the live run is only used for development iteration.

**RISK-6 (LOW): Open questions unresolved**
OPEN-Q-1 through OPEN-Q-5 must be resolved before their dependent stories start. If OPEN-Q-1 (pgvector inline vs callback) is unresolved at STORY-006 start, default to inline pre-fetch (simpler) and document the limitation.
